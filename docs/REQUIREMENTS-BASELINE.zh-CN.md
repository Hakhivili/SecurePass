## 1. 项目目标（一句话）

交付一款**个人使用、单机离线优先、跨平台**的桌面密码管理工具：既能用系统级安全随机数生成 8–20 位随机密码，
又能用主密码保护的本地加密密码库管理用户**已有**的账户与密码原文，具备分类/搜索/复制、自动锁定、
剪贴板清理、加密备份与可回滚恢复；**不联网、不采集、不提供默认明文导出**，以“功能完整、操作简洁、
数据安全、可恢复”为主要目标。

> 两条边界（任务书明确强调，后续开发不得违反）：
>
> 1. **8–20 位只限制生成器**；密码库必须能保存更长的已有密码，支持空格/中文等字符，**不得截断或去首尾空格**。
> 2. **编辑密码库记录 ≠ 修改网站真实账户密码**；首版只管理本地记录。

---

## 2. 首版范围（任务书 §2）

**首版必须完成**：8–20 位随机密码生成｜手动录入及编辑账户密码｜搜索、分类、复制｜本地加密密码库｜主密码解锁与自动锁定｜加密备份与恢复。

**后续版本考虑**：>20 位生成模式与口令短语｜CSV 及其他密码管理器导入｜重复密码检查、密码历史｜多设备端到端加密同步｜生物识别解锁｜浏览器扩展与自动填充。

**明确不做**：团队共享、远程账户注册、网站密码自动修改、云端服务。

## 3. 功能需求清单（任务书 §3–§5）

### 3.1 随机密码生成器

长度 8–20（默认 16，滑块或数字输入）｜大小写/数字/符号可勾选（默认全开）｜可排除易混淆字符（0/O、1/l/I）｜
默认每种已选字符类型至少出现 1 个｜全不选或排除后无法生成时给出明确提示｜使用操作系统或成熟库的安全随机源，
禁止普通随机函数/时间戳/自制算法｜抽取与打乱须无偏｜支持重新生成、复制、保存到密码库｜
重新生成不得覆盖已保存记录｜未保存结果不进入持久化历史｜对弱配置给出提示，不使用“绝对安全”类文案。

### 3.2 密码库

字段：记录编号（系统生成唯一）、名称（必填）、登录账号、密码（存原文，默认隐藏）、
网站/应用地址（可选）、分类/标签（可选）、备注（可选）、创建与修改时间（系统维护）。

要求：增/查/改/删｜可手动输入或粘贴任何来源密码｜密码字段支持 1–1024 个 Unicode 字符，超限明确拒绝、
不静默截断｜保存时不改大小写、首尾空格与内容｜按名称/账号/网站/标签搜索，**首版不搜索密码内容**｜
**允许同网站多账户，重复录入时提醒，由用户决定是否保留**｜编辑有保存与取消，取消不改原记录｜
删除前确认并说明“已有备份中的记录不会同步删除”｜提供显示/隐藏、复制账号、复制密码｜
**自动锁定后清除界面明文与搜索结果**。

### 3.3 主密码与锁定

首次使用创建库并两次确认｜主密码不受 8–20 限制｜建议最少 15 字符、允许空格与长口令｜
启动默认锁定、支持手动锁定｜默认无操作 5 分钟自动锁定（可调），系统锁屏/休眠即锁定｜
改主密码必须先验证当前密码，过程具备失败回滚能力（中断不得导致库打不开）｜
不提供主密码找回，创建时明确“忘记主密码后备份也无法解密”｜备份使用创建时主密码，
改主密码不改变旧备份的解锁密码。

### 3.4 备份与恢复

手动导出加密备份｜备份含格式版本、必要加密参数与完整密文｜恢复前验证密码与文件完整性｜
恢复采用“替换当前库”，替换前保留当前库的加密备份｜密码错误/文件损坏/版本不兼容时拒绝恢复且不覆盖现有数据｜
**不提供默认明文导出**。

### 3.5 安全设计（任务书 §4）

- 保护目标：设备丢失后库文件被复制、备份泄露、应用意外暴露密码、文件被篡改、异常写入；**不承诺**在系统已被恶意软件控制、有键盘记录器或解锁期间内存被读取时仍安全。
- 存储方式：业务密码必须**可解密**存储（不能只存哈希）且落盘加密；账户、网址、备注一并加密；
  成熟库提供的认证加密（如 AES-256-GCM），同一密钥下 nonce 不重复；主密码不得明文落盘。
- 密钥管理：主密码 → Argon2id → 密钥加密密钥（KEK）→ 解密随机数据密钥（DEK）→ 解密密码库；
  每个库独立随机盐；派生参数连格式版本一起保存；**不得直接把主密码当加密密钥**；改主密码时重新派生并重封装数据密钥。
- 明文暴露控制：日志/错误报告/临时文件/配置不得记录明文密码、主密码或密钥；首版不接入会采集敏感内容的分析或崩溃上报；
  复制后默认 30 秒尝试清空剪贴板（仅当内容仍为本次复制内容），并提示“不能保证删除系统或第三方剪贴板历史”；
  锁定时释放密钥与明文引用；界面失败重试延迟**不能替代**抗离线破解的密钥派生设计。

### 3.6 界面（4 个）

初始化/解锁｜密码生成器｜密码库（搜索、分类、列表、详情、新增编辑）｜设置（自动锁定、剪贴板、改主密码、备份恢复）。

### 3.7 技术架构分层（任务书 §6）

界面层 / 生成服务 / 密码库服务 / 安全服务 / 存储服务 / 备份服务 / 平台适配（剪贴板、锁屏事件、文件权限、安装打包）分离；
加密组件必须用持续维护的成熟实现，不自行编写密码算法；首版可限制同一密码库只允许一个进程写入。

### 6.1 第 2 条（开源）带来的约束

- **公开可读**：命名、注释与文档需要自洽，`npm run format:check`、lint、typecheck、test、build 必须全绿（CI 已覆盖）。
- **不得入库**：任何个人数据、密码库文件（`vault.securepass` / `.bak`）、密钥、令牌、本机绝对路径。
- **需补齐的开源交付物**：根目录 `SECURITY.md`（漏洞报告渠道）、第三方依赖与许可证清单、应用图标、README 徽章与截图。

- **许可证兼容性**：运行时依赖闭包共 77 个包，**全部为 MIT**，与项目 MIT 许可无冲突（详见 `OPEN-SOURCE-CHECKLIST.zh-CN.md`）。

## 7. 建议的开发顺序（任务书 §10 末段）

任务书建议：**先验证“创建库 → 加密保存 → 关闭 → 解锁 → 备份恢复”的完整数据安全闭环，再做生成器与管理界面**。
当前该闭环已实现并通过单元测试，因此后续顺序建议为：

0. ✅ **开源基线（已完成）**：统一 Prettier 格式（此前 `npm run format:check` 在原始代码上失败，涉及 27 个文件）、
   把 `format:check` 纳入 CI、补充 VS Code 工程配置。
1. ✅ **补齐验收证据（已完成）**：落盘明文扫描（第 7 项）、中断模拟（第 10 项）、剪贴板单测（第 11 项）、
   1000 条性能基准（第 12 项）、全新环境端到端恢复（第 9 项）——见 `docs/TEST-REPORT.zh-CN.md`。
2. ✅ **补齐首版功能缺口（已完成）**：重复录入提醒；剩余可选项为剪贴板历史提示与“编辑 ≠ 改真实账户”文案。
3. ✅ **修复代码缺陷（已完成）**：编辑丢失 `lastUsed`、保存失败清空表单、主题/语言设置未生效。
4. **进行中 · 补齐交付物**：测试报告 ✅；用户手册 ❌；第三方依赖与许可证清单 ⚠️（见开源清单）。
5. **下一步 · 用户手册与可选文案提示**，然后是 v0.5 扩展：导入导出（CSV/其他密码管理器）、重复密码检查、
   密码历史、生物识别适配层。
6. **开源发布**：按 `OPEN-SOURCE-CHECKLIST.zh-CN.md` 逐项确认后，打 tag `v0.1.0` 并发布源码与未签名安装包。

# 路线图（三个里程碑）

> 目标：在「永久免费、零遥测、离线优先」的前提下，把 SecurePass 分三步做完——
>
> 1. **里程碑一（M1）**：一个个人自用、比记事本好得多的密码管理器，且可以公开上传到 GitHub；
> 2. **里程碑二（M2）**：覆盖个人日常使用的所有可能场景，成为一个真正意义上好用的工具；
> 3. **里程碑三（M3）**：达到商业级品质。
>
> 版本号是**范围**而不是**日期承诺**：每个版本做完并通过门禁才发布，更新节奏可能变慢，
> 但不跳票、不半成品（见 `docs/MAINTENANCE.zh-CN.md`）。

## 0. 总览

| 里程碑            | 一句话目标                               | 出口标准（DoD）                                                              | 包含版本      | 状态                    |
| ----------------- | ---------------------------------------- | ---------------------------------------------------------------------------- | ------------- | ----------------------- |
| **M1 自用合格**   | 自己天天用、敢发给朋友、敢开源           | 加密与备份可信、日常操作顺手、无遥测、能装能卸、仓库可公开                   | 0.1.0 + 0.2.0 | 0.1.0 ✅ / 0.2.0 进行中 |
| **M2 真正好用**   | 不用再为任何个人场景去开记事本或另存网页 | 能搬进来、能生成各种形状的密码、有两步验证、能看出库里哪条该换、安全性跟得上 | 0.3.0 + 0.4.0 | 未开始                  |
| **M3 商业级品质** | 陌生人可以像信任商业产品一样信任它       | 质量可度量、构建可复现、三平台验收、有威胁模型与安全公告流程                 | 0.5.0 + 1.0.0 | 未开始                  |

## 1. 里程碑一：个人自用的合格密码管理器（可开源上传）

### 1.1 判定标准

- **数据不丢**：落盘无明文、原子写 + `.bak`、篡改可检测、备份可恢复、恢复中断不毁库 → **已达成**；
- **日常够用**：生成 / 保存 / 编辑 / 搜索 / 分类 / 复制 / 锁定 / 加密备份，全键盘可达 → **已达成**；
- **敢发给别人**：能装、能卸、有图标与元数据、有哈希、有说明、无遥测 → **0.2.0 完成**；
- **敢公开**：README / LICENSE / SECURITY / 第三方许可 / 用户手册 / Issue 模板齐全，无本机路径与个人信息 → **0.2.0 完成**。

### 1.2 0.1.0（已交付）

| 内容     | 说明                                                                            |
| -------- | ------------------------------------------------------------------------------- |
| 密码库   | Argon2id（3 轮 / 64 MiB / 并行 4）+ AES-256-GCM，AAD 绑定两份数据               |
| 生成器   | 8–20 位、字符类型开关、排除易混淆、熵值与强度建议、重复录入提醒                 |
| 记录管理 | 新增 / 编辑 / 删除（可撤销）/ 收藏 / 分类 / 标签 / 搜索 / 复制 / 显示密码       |
| 会话安全 | 主密码解锁、按需解锁、空闲 + 失焦自动锁定、锁屏与休眠联动、剪贴板定时清除       |
| 备份     | 加密备份导出与恢复（32 MB 上限、二次确认、`pre-restore` 副本）                  |
| 界面     | 令牌驱动主题（浅/深/跟随系统 + 6 套强调色）、中英双语、自绘标题栏、窗口状态记忆 |
| 工程     | 40 个源文件量级、跨平台打包、覆盖率门槛 78/85/78/78、真实产物 E2E 冒烟          |

## 2. 里程碑二：覆盖个人日常使用的所有场景（真正好用）

### 2.1 判定标准

- 从 Chrome / Bitwarden / KeePass 一次搬完，不用手抄；
- 需要什么形状的密码都能生成（长口令、口令短语、指定字符集）；
- 两步验证直接在应用里看，不用另一个 App；
- 能一眼看出库里哪些密码弱、哪些重复、哪些久未更新；
- 安全参数跟得上时代（更强 KDF、可迁移、有恢复码、猜主密码有退避）。

### 2.2 0.3.0 安全可签字

| 项目            | 说明                                                                        |
| --------------- | --------------------------------------------------------------------------- |
| 威胁模型        | `docs/THREAT-MODEL.zh-CN.md`：资产、攻击面、信任边界、已接受的残余风险      |
| KDF 提升        | 默认 `256 MiB / t=4`，并提供密钥迁移（旧库首次解锁后自动重包裹 DEK）        |
| 主密码强度      | 复用强度/字典检查（对齐 zxcvbn 思路），创建时给出可读建议                   |
| 恢复码          | 随机生成的 24 词 / 160-bit 恢复码，用于主密码遗忘时恢复（本地保存，不联网） |
| 解锁退避        | 连续失败指数退避（1s → 30s 上限），KDF 仍是主要成本                         |
| 属性测试 + fuzz | 密码库解析/解密路径的属性测试与 ≥24 小时 fuzz 语料                          |

### 2.3 0.4.0 日常可用

| 项目       | 说明                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| 导入       | CSV（通用格式）、Bitwarden JSON、KDBX 只读；导入前预览与冲突处理，导入后清空中间文件 |
| 导出       | 仅加密备份（默认）；明文导出需二次确认并提示风险                                     |
| 生成器增强 | 随机串 8–64 位、口令短语（4–8 词，EFF 词表）、自定义字符集                           |
| 密码历史   | 每条记录保留最近 N 版（默认 5），加密存储，可关闭、可清空                            |
| TOTP       | 内置验证码（本地计算），二维码/手动密钥录入                                          |
| 健康检查   | 弱密码、重复密码、久未更新、缺失 TOTP 的汇总面板                                     |
| 搜索增强   | 覆盖备注（可开关，默认关）、按标签/收藏筛选                                          |

## 3. 里程碑三：商业级品质

### 3.1 判定标准

- 质量是**可度量**的：启动时间、内存、包体积、KDF 耗时写进 CI 断言，超预算即失败；
- 构建是**可复现**的：固定工具链与依赖锁，产物哈希可复算；
- 三平台（Windows / macOS / Linux）都过一遍验收清单，而不是只在 Windows 试过；
- 有威胁模型、属性测试/fuzz、外部审查记录与安全公告流程；
- 文档覆盖「用户 / 贡献者 / 维护者」三类读者。

### 3.2 0.5.0 质量可度量

| 项目         | 说明                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| QUALITY 预算 | 启动时间、内存、包体积、KDF 耗时写入 CI 断言，超预算即失败                             |
| E2E 进 CI    | `tools/e2e-smoke.mjs` 接到 CI（xvfb / Playwright Electron）                            |
| 视觉回归     | 关键界面截图基线比对                                                                   |
| 分目录覆盖率 | 主进程 / 渲染层 / 工具分别设阈值                                                       |
| 生物识别     | 仅做可行性验证：Windows Hello / macOS Touch ID 作为 DEK 的二次门禁，**不能替代主密码** |

### 3.3 1.0.0 商业级

- 三平台验收（Windows 已实测；macOS 未签名说明；Linux AppImage/deb 冒烟）；
- 可复现构建（固定工具链与依赖锁，产物哈希可复算）；
- 兼容性矩阵（Windows 10/11、macOS 13+、主流 Linux 发行版）；
- 安全公告流程（Advisories + `SECURITY.md` 升级路径）；
- 用户手册补全（导入、TOTP、恢复码、健康检查）。

## 5. 明确不做

- ❌ 云端同步服务、账号体系、远程注册（只保留未来可选的第三方同步方案调研）；
- ❌ 团队共享、组织权限、审计后台；
- ❌ 自动修改网站密码、浏览器云同步注入；
- ❌ 任何形式的遥测、使用统计、广告、付费墙；
- ❌ 付费签名证书（Azure Trusted Signing）与付费第三方审计——免费方案（SignPath、社区 review）优先。

## 6. 版本与数据兼容

- 新增字段必须向后兼容：旧库解锁时由 `validatePayload` / `repairItems` / `normalizeSettings` 自动修补；
- 破坏性格式变更必须递增 `formatVersion` 并补迁移测试；
- 每个版本发布前跑：`format:check` → `typecheck` → `lint` → `test:coverage` → `build` → `e2e-smoke`。
